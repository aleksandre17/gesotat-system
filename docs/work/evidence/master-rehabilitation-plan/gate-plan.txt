            -PactiveModules overrides it, so :mobile is in the default build
    FACT 2  api/build.gradle L19-24 declares, under conditions that both hold by default,
            an implementation dependency on project(':mobile'). The OUT-OF-SCOPE module is
            therefore on the API compile and runtime classpath and is packaged into the API
            artifact. CLASS: build + packaging coupling, ACTIVE, DEFAULT-ON.
    FACT 3  org.base.api.config.MobileModuleConfig - an API-owned class carrying
            ConditionalOnProperty(name=mobile.enabled, matchIfMissing=true) and a
            ComponentScan of basePackages org.base.mobile that is COMMENTED OUT.
            No mobile bean loads today, but the switch, the property and the default-true
            condition are live in API source. CLASS: runtime coupling, DORMANT, and it
            RE-ARMS SILENTLY if three lines are uncommented - no config change anywhere.
    FACT 4  API resources reference the out-of-scope package: org.base.mobile logger levels
            in application-dev.yml, application-prod.yml and logback-spring.xml.
            CLASS: configuration / governance.

  MINIMUM API-SIDE ISOLATION REQUIREMENT -> W-30 (Stage C), EL-13, PR-17.
  Every action is inside backend/api or the backend build files. NOTHING in the excluded
  module is changed, rehabilitated or read further.
    1. sever the build edge in api/build.gradle (or invert to explicit opt-in)
    2. make activeModules explicit so a build cannot absorb a sibling by directory scan
    3. delete MobileModuleConfig - an excluded module must not be re-armable by uncommenting
    4. remove the 3 org.base.mobile references from API resources
    5. PR-17 fitness test: the API module may not declare a project dependency on an
       out-of-scope module, reference its packages, or reintroduce scanned inclusion

  EXIT CRITERION: the API Platform builds, tests, packages and runs with :mobile absent from

  the API Platform - which is what OUT OF SCOPE must mean operationally.

  W-30 IS NOT mobile rehabilitation, not a migration, not an elimination of that module, and
