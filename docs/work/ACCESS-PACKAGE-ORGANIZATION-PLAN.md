# Access package-ის ორგანიზების გეგმა

თარიღი: 2026-09-19  
სტატუსი: შეთანხმებული მიმართულება; იმპლემენტაცია დაგეგმილია.  
მოცულობა: ამ ეტაპზე დაფიქსირებულია მომხმარებელთან შეთანხმებული გადაწყვეტილებები. ეს დოკუმენტი შესრულების მტკიცებულება არ არის.

## მიზანი

ერთ Access package-ში მკაფიოდ გამოიყოს მომხმარებლის შესავსები მონაცემები, იდენტობისა და სქემის აღწერები, კლასიფიკატორები და წყაროს კვალი. მომხმარებელმა მარტივად უნდა დაინახოს, სად შეაქვს მონაცემები და რომელი ნაწილი აღწერს დამტკიცებულ კონტრაქტს.

## შეთანხმებული ორგანიზება

ვინარჩუნებთ ერთ `.accdb` ფაილს. Access-ის Navigation Pane-ში ვიყენებთ კატეგორიებსა და ჯგუფებს, რომლებიც ცხრილებსა და, საჭიროების შემთხვევაში, ფორმებს ვიზუალურად აჯგუფებს.

| ჯგუფი | დანიშნულება და შიგთავსი |
|---|---|
| **შესავსები მონაცემები** | კონტრაქტით რედაქტირებადი მონაცემების ცხრილები ან ფორმები; KIDS-ის მაგალითია `__ent_kids_resource`. |
| **იდენტობა და სქემა** | Package-ისა და dataset-ის იდენტობა, სვეტები, გასაღებები, კავშირებისა და projection-ების აღწერები; მათ შორის `__gs_package`, `__gs_dataset`, `__gs_field`, `__gs_key`, `__gs_relation`, `__gs_page`, `__gs_projection`. |
| **კლასიფიკატორები** | კონტრაქტით განსაზღვრული დასაშვები კოდები და მნიშვნელობები. ჯგუფში ყოფნა თავისთავად მათი რედაქტირების უფლებას არ ნიშნავს. |
| **წყაროს კვალი** | Provenance და lineage ჩანაწერები, მათ შორის `__raw_document`. |

ფაილის გახსნისას მომხმარებლის საწყისი სამუშაო ხედი იქნება **„შესავსები მონაცემები“**. ჯგუფების სახელები იქნება ქართულად.

კანონიკური ცხრილების სახელები, სვეტები, გასაღებები, იდენტობები და კავშირები შენარჩუნდება. კერძოდ, `__ent_kids_resource` დარჩება ამავე კანონიკური სახელით. დაჯგუფება არ შექმნის მონაცემების დუბლირებულ ცხრილებს.

## დაცვის წესი და authority

### სტატისტიკური ნაწილის შემდგომი ევოლუცია

2026-09-19-ის დამატებითი შეთანხმება: სტატისტიკური კონტრაქტი უნდა იყოს ყველა პროექტისთვის საერთო, ნეიტრალური სახელებით, მხოლოდ საჭირო სვეტებით და მარტივი მრავალგანზომილებიანი/მრავალსაზომიანი შევსებით. დეტალური დიზაინი, არსებული სვეტების ცვლილების რუკა და შესრულების ეტაპები აღწერილია [საერთო სტატისტიკური კონტრაქტის გეგმაში](COMMON-STATISTICAL-CONTRACT-PLAN.md).

ზემოთ სახელებისა და სქემის შენარჩუნების მოთხოვნა ეხება მიმდინარე package-ის ვიზუალურ ორგანიზებას. სტატისტიკური სქემის ცვლილება განხორციელდება ცალკე contract revision-ით, compatibility/crosswalk/reconciliation მტკიცებულებით; არსებული R8-ის ჩუმი გადარქმევა ან საჭირო lineage-ის წაშლა დაუშვებელია. `__ent_kids_resource` ამ სტატისტიკური ცვლილების ფარგლებში არ იცვლება.

Navigation Pane-ის დაჯგუფება ან ობიექტის დამალვა არის ვიზუალური ორგანიზება და არ წარმოადგენს უსაფრთხოების საზღვარს.

სქემისა და იდენტობის შესაბამისობა იმპორტისას უნდა შემოწმდეს დამტკიცებულ, versioned Control Plane contract-თან. შეუსაბამობა უნდა დაფიქსირდეს validation-ის შედეგად და შეაჩეროს შესაბამისი მიღება; მომხმარებლის მიერ შეცვლილი metadata ავტომატურად ვერ გახდება ახალი contract authority.

რედაქტირებადი მონაცემებისა და ტექნიკური აღწერების გამიჯვნა უნდა ეფუძნებოდეს კონტრაქტის metadata-ს. Generic მექანიზმში KIDS-specific სახელების სია ან business branching არ უნდა დაემატოს.

პასუხისმგებლობა: Access package-ის გენერაცია და წარმოდგენა — Delivery; კონტრაქტის ავტორიტეტი — Control Plane; მიღების შემოწმება — Ingestion; ავტორიზაცია — Security.

## შემდგომ დასაზუსტებელი საკითხები

- Navigation Pane-ის ჯგუფების გენერაციისა და შენახვის ტექნიკური გზა და მხარდაჭერილი Access ვერსიები.
- საწყისი ხედის დაყენების მექანიზმი.
- რომელი მონაცემები გამოჩნდება პირდაპირ ცხრილებად და სად იქნება საჭირო შესავსები ფორმა.
- Metadata-ში ჯგუფისა და რედაქტირებადობის აღწერის საჭიროება და მისი versioning/compatibility წესი.

ცალკე `.accdb` ფაილებად დაყოფა მიმდინარე შეთანხმებაში არ შედის. ასეთი ცვლილება მოითხოვს package contract-ისა და ფაილებს შორის იდენტობის ცალკე განხილვას.

## იმპლემენტაციის მიღების კრიტერიუმები

- [ ] Access-ში ჩანს ოთხივე შეთანხმებული ჯგუფი და საწყისი ხედი არის „შესავსები მონაცემები“.
- [ ] ცვლილებამდე და ცვლილების შემდეგ ემთხვევა მონაცემები, კანონიკური სახელები, გასაღებები და კავშირები; მთლიან ფაილს ექნება ახალი checksum და შესაბამისი build provenance.
- [ ] დაჯგუფებული package გადის მოქმედ contract validation-ს.
- [ ] იდენტობისა და სქემის დაუშვებელი ცვლილების negative შემოწმება მიღებას ბლოკავს.
- [ ] დაჯგუფება განმეორებით გენერაციაზე არ ქმნის დუბლირებულ ჯგუფებს ან ობიექტებს.
- [ ] შედეგი შემოწმებულია Access-ში და შენახულია runtime ან reproducible test evidence. წინა immutable artifact ხელმისაწვდომია rollback-ისთვის.

ამ კრიტერიუმების შესრულებამდე სტატუსი რჩება **დაგეგმილი**.
